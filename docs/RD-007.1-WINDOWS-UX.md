# RD-007.1 — Experiência Windows para cliente final

**Status: concluída localmente e complementada pela RD-007.2. Beta 2 ainda não publicada.**

## Motivo da correção

A `v0.1.0-beta.1` comprovou o funcionamento do motor técnico, mas não atende ao requisito de uso por cliente leigo. Ao abrir o EXE por duplo clique sem argumentos, a aplicação apresenta ajuda em terminal e encerra.

O produto Windows deve exigir do cliente apenas **baixar o arquivo e abrir o executável**.

## Objetivo

Fluxo obrigatório:

```text
baixar EXE
→ duplo clique
→ janela Technolife
→ detectar RustDesk
→ instalar se necessário
→ aplicar configuração Technolife
→ validar
→ informar conclusão
```

Não deve ser necessário abrir PowerShell, Prompt de Comando ou informar parâmetros.

## Escopo

1. Alterar a execução sem argumentos para iniciar automaticamente o fluxo completo equivalente a `setup`.
2. Criar GUI Windows mínima com progresso, sucesso e erro.
3. Eliminar terminal visível no fluxo normal do cliente.
4. Manter uma única confirmação UAC para o fluxo administrativo, conforme refinado na RD-007.2.
5. Reutilizar o motor existente sem reimplementar Core, detector, download, SHA-256, instalação, configuração, validação ou logs.
6. Preservar `status`, `configure` e `setup` como comandos técnicos.
7. Testar RustDesk presente, ausente, UAC recusado, internet indisponível e execução repetida.
8. Preparar a correção para futura publicação como `v0.1.0-beta.2`.

## Interface mínima

A janela deve comunicar somente o necessário:

```text
Technolife - Configuração de Acesso

Verificando RustDesk...
Instalando RustDesk...
Ativando acesso remoto...
Configurando acesso remoto...
Validando configuração...

Configuração concluída com sucesso.

[ Concluir ]
```

Em caso de falha, deve apresentar mensagem simples, código quando útil e opção de tentar novamente ou fechar. Detalhes técnicos permanecem nos logs.

## Implementação

- projeto WinForms `.NET 8` em `src/Technolife.RustDesk.Windows`;
- saída `WinExe`, sem console no fluxo normal;
- setup iniciado automaticamente quando a janela é exibida, sem botão `Iniciar`;
- composição das implementações existentes por `WindowsSetupWorkflowRunner`;
- progresso opcional no Core com estados independentes de WinForms;
- operações aguardadas de forma assíncrona para preservar a responsividade;
- sucesso com botão `Concluir`;
- falha com código de suporte, `Tentar novamente` e `Fechar`;
- publicação Windows alterada para usar o projeto GUI, mantendo a CLI técnica separada.

## Validação local por duplo clique

Teste realizado pelo Explorer em `artifacts/windows-x64/Technolife-RustDesk-Windows.exe`:

1. nenhuma janela de terminal apareceu;
2. a janela Technolife abriu;
3. o processo começou automaticamente;
4. RustDesk 1.4.9 existente foi detectado;
5. nenhuma reinstalação foi realizada;
6. a configuração terminou com exit code zero;
7. a validação inicial retornou `Applied`;
8. a mensagem de sucesso permaneceu visível;
9. o botão `Concluir` fechou a aplicação.

O cenário físico sem RustDesk não foi executado nesta máquina porque exigiria remover
uma instalação funcional. Ausência, instalação, UAC recusado, falha de download e
idempotência permanecem cobertos por testes automatizados; o teste físico será feito
em uma máquina limpa antes da Beta 2.

## Complemento RD-007.2

O teste real posterior mostrou que a experiência gráfica correta não bastava: o
fluxo ainda aceitava exit code zero de `--config` sem confirmar os valores e não
garantia a existência e execução do serviço. A RD-007.2 preservou esta GUI e
acrescentou:

- elevação única antes da abertura da janela principal;
- criação do serviço `RustDesk` com `--install-service` quando ausente;
- garantia de estado `Running` antes da configuração;
- execução administrativa de `--config`;
- releitura de `custom-rendezvous-server`, `relay-server` e `key` por `--option`;
- sucesso somente com resultado `Verified`;
- falha `ValidationFailed` quando exit code zero não altera os valores.

O novo teste por duplo clique foi aprovado com RustDesk 1.4.9 existente sem abrir ou
desbloquear Rede e sem clicar em iniciar serviço. A interface mostrou sucesso, o log
registrou `Applied` e `Verified`, e a inspeção posterior mostrou RustDesk `Pronto` e
o serviço ativo. A tela de Rede permaneceu bloqueada; os valores foram confirmados
automaticamente pela CLI oficial, não por alteração manual da interface.

Detalhamento: [RD-007.2-WINDOWS-SERVICE-CONFIG.md](RD-007.2-WINDOWS-SERVICE-CONFIG.md).

## Critérios de aceite

- duplo clique inicia o processo sem parâmetros;
- nenhum terminal é exibido no uso normal;
- usuário acompanha o progresso em janela gráfica;
- RustDesk ausente é instalado automaticamente;
- RustDesk existente não é reinstalado;
- serviço RustDesk é criado e iniciado sem ação manual;
- configuração Technolife é aplicada;
- resultado é relido, comparado e exibido apenas como `Verified`;
- erros são compreensíveis para usuário leigo;
- logs técnicos continuam disponíveis;
- execução repetida permanece idempotente;
- testes automatizados existentes continuam passando;
- Beta 2 é testada localmente por duplo clique antes de publicação.
